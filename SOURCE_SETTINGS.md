# Подключение Google Sheets из CRM

Кнопка «Подключение таблицы» открывает настройки без добавления четвёртого рабочего раздела. Владелец вводит URL опубликованного Google Apps Script и ключ. Сохранение выполняет проверку чтения; данные клиентов не загружаются в ответ проверки и ключ не возвращается браузеру. После сохранения доступны импорт и приостановка обмена. Существующий интервал обновления — 60 секунд при открытой CRM.

Это подключение совместимого моста, а не универсальный OAuth-коннектор произвольной таблицы. Для MOFT.RACE мост уже подготовлен. Простая ссылка Google Sheets не предоставляет серверу доступ. Маппинг колонок остаётся в мосте; назад передаются только статус, статус продажи и примечания.

## Установка на сервере — обязательно до включения

1. Сделать резервную копию базы и применить миграцию `drizzle/0002_source_settings.sql` один раз. Она добавляет только таблицу настроек.
2. Настроить случайный секрет `CRM_SETTINGS_KEY` (минимум 32 символа) через защищённые переменные сервера. Сохранить его отдельно для восстановления: без него зашифрованный ключ моста не расшифровать. Не помещать значение в GitHub, клиентский JS, логи или публичные файлы.
3. Установить `CRM_ADMIN_EMAILS` — email владельцев через запятую; значение по умолчанию сохраняет текущего владельца проекта. Сотрудникам разрешена обычная работа с клиентами, настройками управляет владелец.
4. Адаптировать `getChatGPTUser` к реальной защищённой серверной сессии, если приложение запущено вне Sites. Нельзя доверять заголовкам `oai-authenticated-*`, присланным из интернета: на Sites их удостоверяет платформа, на самостоятельном сервере этого механизма нет. На новом сервере необходимо сначала проверить, что анонимные GET/POST CRM и настроек отклоняются, а сотрудник получает 403 для настроек.
5. Изменения рассчитаны на текущий GitHub-код с Cloudflare D1. Для другого серверного адаптера требуется сопоставить получение env/базы с реальным развёртыванием. Сам по себе merge не гарантирует обновление уже работающего сайта.
6. Войти владельцем, открыть настройки, указать мост и ключ, проверить и сохранить, затем загрузить лиды. Сверить ID и поля с источником. Не использовать публичные страницы или скриншоты для передачи ключа.

Переменные `MOFT_BRIDGE_URL` и `MOFT_BRIDGE_SECRET` остаются резервным вариантом, пока запись настройки не создана. После сохранения в интерфейсе используется зашифрованная запись базы. Приостановка блокирует импорт/экспорт и не удаляет клиентов; несинхронизированные изменения остаются для повторной отправки. Нельзя переключить URL при существующих связанных лидах: перенос на другой источник выполняется отдельно, чтобы не смешать таблицы. Для нового deployment того же моста также потребуется отдельная проверка и перенос настройки.

Проверки: `node --test integration/source-settings.test.mjs`, `node integration/bridge.test.mjs`, TypeScript. Проверка реального self-hosted сайта и развёртывание требуют доступа к его конфигурации.
